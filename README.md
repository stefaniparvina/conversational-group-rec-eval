# A Framework for Evaluating Preference Fairness in Conversational Group Recommendation

---

## Overview

This repository contains the code and data for a **two-module evaluation framework**
that studies whether conversational group-recommendation dialogs handle individual
preferences fairly — looking at both the **outcome** of each conversation and the
**process** by which it was reached.

- **Module 1 (structural).** Deterministic, formula-based metrics computed directly
  from each dialog's ratings and votes. Answers RQ1, RQ2, RQ4.
- **Module 2 (process).** An LLM judge (OpenAI GPT-4o) scores qualities of the
  conversation itself on a subset of structurally unfair groups. Answers RQ3.

The simulation data builds on Barile et al. (2024), covering four group
configurations (uniform, divergent, coalitional, minority) across **8,000 simulated
multi-turn restaurant-recommendation dialogs**, generated by four open LLMs
(Gemma, LLaMA, Mistral, OLMo — 2,000 each). **7,624 of 8,000 groups (95.3%) reached
consensus**. All hypothesis tests run on the consensus groups.

---

## Research questions and hypotheses

- **H1** — Conversational outcomes produce lower group welfare than the best formal
  aggregation strategy. *(Module 1)*
- **H2** — Group preference structure significantly affects fairness (MinSat,
  MajMinGap). *(Module 1)*
- **H3** — Within the structurally-unfair subset (MinSat < 0.20 **and**
  MajMinGap > 0.30), process metrics carry diagnostic information beyond the
  structural metrics. *(Module 2)*
- **H4** — No Big Five trait is meaningfully correlated with individual satisfaction
  (|Pearson r| < 0.05 per trait). *(Module 1)*

The **H3 subset** is **1,376 groups / 8,524 agents** (1,032 groups remain after
removing the 344 audit-flagged judge outputs).

## Repository structure

```
conversational-group-rec-eval/
├── data/
│   ├── raw/            # Raw per-LLM simulation output (gemma, llama, mistral, olmo) — git-ignored
│   ├── full_dataset/   # The 8,000 merged group_simulation_*.json — git-ignored (too large)
│   ├── sample/         # A small set of example group_simulation_*.json, so the input format is visible without the full dataset
│   ├── results/        # All computed metrics and analysis outputs (see "Outputs" below)
│   └── validation/     # Judge-validation set, human annotation workbook, and the agreement report
├── src/
│   ├── module1/                      # Structural analysis (RQ1, RQ2, RQ4)
│   │   ├── merge_dataset.py          # Merge the raw per-LLM folders into full_dataset/
│   │   ├── evaluation_framework.py   # Compute the structural metrics per group
│   │   ├── reproduce_stats.py        # Descriptive statistics
│   │   └── hypothesis_tests.py       # Formal tests for H1, H2, H4
│   └── module2/                      # Process-level LLM evaluation (RQ3)
│       ├── select_validation_set.py  # Pick the 15 transcripts for judge validation
│       ├── build_annotation_workbook.py  # Build the human-annotation workbook
│       ├── validate_judge.py         # Judge vs. human agreement
│       ├── llm_evaluator.py          # The GPT-4o judge; scores the 4 process metrics
│       ├── build_h3_dataset.py       # Join Module 1 + Module 2 into the agent-level dataset
│       └── regression_h3.py          # Nested OLS regression for H3
├── .env                              # OPENAI_API_KEY (Module 2 only; never committed)
└── README.md
```

> `data/raw/` and `data/full_dataset/` are excluded from version control because of
> their size — use `data/sample/` to see the input format, and re-create the full
> dataset with `merge_dataset.py` if you have the raw folders.

### Outputs (written to `data/results/`)

| File | Produced by | What it holds |
|---|---|---|
| `results.csv` / `results.json` | `evaluation_framework.py` | Structural metrics per group (and per agent) |
| `stats_output.xlsx` / `.txt` | `reproduce_stats.py` | Descriptive statistics, one sheet per section |
| `hypothesis_tests_output.xlsx` | `hypothesis_tests.py` | H1, H2, H4 test tables |
| `llm_results.jsonl` / `llm_results_summary.csv` | `llm_evaluator.py` | Raw and flattened judge output |
| `h3_agent_level.csv` | `build_h3_dataset.py` | Agent-level dataset fed to the H3 regression |
| `regression_h3_output.xlsx` / `.txt` | `regression_h3.py` | H3 regression + robustness checks |

Judge-validation outputs (the per-metric agreement report) are written to
`data/validation/`.

## Pipeline — run the scripts in this order

Run every command from the repo root (`conversational-group-rec-eval/`). Each step
uses the output of the previous one, so the order matters. Module 2 depends on
`results.csv` / `results.json` from Module 1.

**Module 1 — structural analysis**

```bash
# 1. Merge the raw per-LLM folders into data/full_dataset/  (skip if full_dataset/ already exists)
python src/module1/merge_dataset.py

# 2. Compute the structural metrics  ->  results.csv / results.json
python src/module1/evaluation_framework.py data/full_dataset/ data/results/

# 3. Descriptive statistics  ->  stats_output.xlsx / .txt
python src/module1/reproduce_stats.py

# 4. Hypothesis tests H1, H2, H4  ->  hypothesis_tests_output.xlsx
python src/module1/hypothesis_tests.py data/results/results.csv data/full_dataset/
```

**Module 2 — process evaluation** (needs an OpenAI API key; the judge run costs money)

```bash
# 5. Run the GPT-4o judge on the H3 subset  ->  llm_results.jsonl
python src/module2/llm_evaluator.py --mode h3

# 6. Join Module 1 + Module 2 into the agent-level dataset  ->  h3_agent_level.csv
python src/module2/build_h3_dataset.py

# 7. The H3 nested regression + robustness checks  ->  regression_h3_output.xlsx / .txt
python src/module2/regression_h3.py
```

**Judge validation** (optional — reproduces the reliability numbers; run before step 5)

```bash
# a. Pick the 15 transcripts to hand-annotate  ->  validation_set.csv
python src/module2/select_validation_set.py

# b. Build the annotation workbook, then fill it in by hand
python src/module2/build_annotation_workbook.py

# c. Have the judge score the same 15 transcripts
python src/module2/llm_evaluator.py --mode validate

# d. Compare judge vs. human  ->  data/validation/judge_validation_report.*
python src/module2/validate_judge.py
```

## Requirements

```bash
pip install pandas numpy scipy statsmodels openpyxl openai
```

- `scipy` is needed by `hypothesis_tests.py`, `statsmodels` by `regression_h3.py`,
  `openpyxl` for every Excel output, and `openai` for the Module 2 judge.
- **Module 2 only:** put your key in a `.env` file at the repo root as
  `OPENAI_API_KEY=sk-...`. The judge is pinned to `gpt-4o-2024-11-20`,
  temperature 0, seed 42.
