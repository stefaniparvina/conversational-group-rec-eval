## TL;DR
 
When LLM agents negotiate a group decision through conversation, is the outcome fair to every member? Outcome metrics can show that someone lost out. They can't show *why*.
 
I built a **two-module evaluation framework** in Python and applied it to **8,000 simulated multi-turn group dialogs** (restaurant choice) generated by four open LLMs (Gemma, LLaMA, Mistral, OLMo):
 
- **Module 1 (structural):** deterministic fairness metrics per group and per agent, compared against **six social-choice aggregation strategies** (Additive, Least Misery, Most Pleasure, Majority, Approval, Fairness).
- **Module 2 (process):** an **LLM-as-a-judge** pipeline (GPT-4o, structured JSON outputs, rubric plus chain-of-thought) that scores *how* each conversation went, **validated against human annotations** and analysed with a **nested OLS regression**.
### Key findings
 
| | Finding |
|---|---|
| **H1** ✅ | The conversations do worse than the best formal strategy: a mean welfare gap of **−0.088**, with **60.8%** of dialogs below the best strategy and only **0.4%** above it. |
| **H2** ✅ | Group preference structure explains about **40%** of the variance in the worst-served member's satisfaction (Kruskal–Wallis ε² = 0.40). Majority voters do better in every configuration. |
| **H3** ✅ | In structurally unfair groups, the LLM-judged process metrics raise the explained variance in individual satisfaction from **R² = 0.41 to 0.53**. Being acknowledged by others predicts higher satisfaction. Conceding under social pressure predicts lower satisfaction. |
| **H4** ✅ | Big Five personality traits show **no meaningful relationship** with satisfaction. All 95% confidence intervals fall within ±0.05 (n = 38,070 agents). |
 
**Takeaway:** structural metrics show *that* an outcome is unfair. Process metrics help explain *why*.

## What this project demonstrates
 
- **LLM evaluation engineering:** a GPT-4o judge pinned to a dated snapshot (temperature 0, fixed seed), OpenAI Structured Outputs against a strict JSON schema, a rubric with anchored scores and a worked calibration example, retries, and an automated structural audit of every judge output.
- **Judge validation:** 15 stratified, blind hand-annotated transcripts. Agreement is measured with Cohen's κ (quadratic-weighted for ordinal scores), plus PABAK for the rare-event metric.
- **Statistics:** Wilcoxon signed-rank and sign tests, Kruskal–Wallis with pairwise Mann–Whitney U tests, Holm–Bonferroni correction, rank-biserial effect sizes, Fisher-z confidence intervals, nested OLS with cluster-robust (Huber–White) standard errors, a joint Wald F-test, VIF checks, and four robustness checks. All hypotheses and decision rules were fixed before the analysis.
- **Data pipeline:** about 8,000 JSON dialogs are turned into group-level and agent-level datasets with reproducible scripts and Excel/CSV reports.
- **Stack:** Python · pandas · NumPy · SciPy · statsmodels · OpenAI API · openpyxl

## Overview
 
The framework has two modules:
 
- **Module 1 (structural).** Deterministic, formula-based metrics computed directly from each dialog's ratings and votes. Answers RQ1, RQ2 and RQ4.
- **Module 2 (process).** An LLM judge (OpenAI GPT-4o) scores qualities of the conversation itself on a subset of structurally unfair groups. Answers RQ3.

The simulation data follows the setup of Barile et al. (2024), covering four group configurations (uniform, divergent, coalitional, minority) across **8,000 simulated multi-turn restaurant-recommendation dialogs**, 2,000 from each of four open LLMs. **7,624 of the 8,000 groups (95.3%) reached consensus.** All hypothesis tests run on the consensus groups.
 
### Metrics
 
| Metric | Module | Meaning |
|---|---|---|
| ISS | 1 | Individual Satisfaction: an agent's rating of the chosen option divided by its highest rating (0–1) |
| GSS | 1 | Group Satisfaction: the mean ISS in the group |
| MinSat | 1 | The ISS of the worst-served member |
| MajMinGap | 1 | Mean ISS of majority voters minus mean ISS of minority voters |
| Welfare Gap | 1 | GSS of the conversation minus the GSS of the best of the six aggregation strategies |
| Mention Rate | 2 | Sentiment-weighted references by other agents to an agent's preference |
| Social Shift | 2 | Whether an agent changed its preference because of group pressure rather than the merits of the options |
| Repetition Index | 2 | How many times an agent restated its preference before anyone acknowledged it |
| Process Quality Score | 2 | A 4-dimension rubric (preferences heard, shifts justified, respect, logical support), scored 0–3 per dimension and normalised to 0–1 |

## Research questions and hypotheses
 
- **H1:** Conversational outcomes produce lower group welfare than the best formal aggregation strategy. *(Module 1)*
- **H2:** Group preference structure significantly affects fairness (MinSat, MajMinGap). *(Module 1)*
- **H3:** Within the structurally unfair subset (MinSat < 0.20 **and** MajMinGap > 0.30), process metrics carry diagnostic information beyond the structural metrics. *(Module 2)*
- **H4:** No Big Five personality trait is meaningfully correlated with an agent's individual satisfaction score (ISS): for every trait, the 95% confidence interval for the correlation lies entirely within ±0.05. *(Module 1)*

The **H3 subset** is **1,376 groups / 8,524 agents**. 1,032 groups remain after removing the 344 audit-flagged judge outputs.

## Reproducing the full pipeline
 
Run every command from the repo root. Each step uses the output of the previous one, so the order matters. Module 2 depends on `results.csv` / `results.json` from Module 1.
 
**Module 1: structural analysis**
 
```bash
# 1. Merge the raw per-LLM folders into data/full_dataset/  (skip if full_dataset/ already exists)
python src/module1/merge_dataset.py
 
# 2. Compute the structural metrics  ->  results.csv / results.json
python src/module1/evaluation_framework.py data/full_dataset/ data/results/
 
# 3. Descriptive statistics  ->  stats_output.xlsx / .txt
python src/module1/reproduce_stats.py
 
# 4. Hypothesis tests H1, H2, H4  ->  hypothesis_tests_output.xlsx
python src/module1/hypothesis_tests.py data/results/results.csv data/full_dataset/
```
 
**Module 2: process evaluation** (needs an OpenAI API key)
 
```bash
# 5. Run the GPT-4o judge on the H3 subset  ->  llm_results.jsonl
python src/module2/llm_evaluator.py --mode h3
 
# 6. Join Module 1 + Module 2 into the agent-level dataset  ->  h3_agent_level.csv
python src/module2/build_h3_dataset.py
 
# 7. The H3 nested regression and robustness checks  ->  regression_h3_output.xlsx / .txt
python src/module2/regression_h3.py
```
 
**Judge validation** (optional; reproduces the reliability numbers; run before step 5)
 
```bash
# a. Pick the 15 transcripts to hand-annotate  ->  validation_set.csv
python src/module2/select_validation_set.py
 
# b. Build the annotation workbook, then fill it in by hand
python src/module2/build_annotation_workbook.py
 
# c. Have the judge score the same 15 transcripts
python src/module2/llm_evaluator.py --mode validate
 
# d. Compare judge vs. human  ->  data/validation/judge_validation_report.*
python src/module2/validate_judge.py
```

## Limitations
 
The dialogs are LLM-simulated, not human. The judge is reliable for Mention Rate and Social Shift, but not for the rare-event Repetition Index (κ ≈ 0, PABAK 0.72), so that metric's null result is treated as inconclusive. See Section V-E of the thesis.
